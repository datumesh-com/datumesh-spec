# Cross-language check

`run.sh` runs the Python (`datumesh`), JavaScript (`@datumesh/verify`) and Rust (`datumesh-core`) implementations and the reference tool over the same inputs: every vector in `vectors/`; randomly generated receipts (about half corrupted, reaching every verification step, with blob content for step 7.7), followed by computed receipts with a `recompute` object whose stored inputs have `asof`s earlier than, equal to or later than the receipt's, and whose evaluation value matches, differs or is absent (`E_EVAL_UNAVAILABLE`, since `spec-0.3.0`); random function descriptors with units, their unit resolution, and random response envelopes (`generate_02.py`); adversarial envelope requests aimed at stale/ok confusion (the receipt's `asof` earlier, equal or later than requested, with and without a requested `asof`, and `age_seconds` present or absent under both outcomes) and receipts for another cell (`generate_envelopes.py`); and mutated cell URIs. The implementations must agree on every byte, hash, signature, level, code reported with success (`E_EVAL_UNAVAILABLE`), unit, envelope outcome and error code. The reference tool is compared too, on every set; since `spec-0.2.0` it agrees on URIs as well.

Since `spec-0.4.0` two more sets: slice-lineage receipts (`generate_slices.py`: computed receipts citing slices, with manifests and members, about half corrupted at each new check of 10.1 step 7.5 and at `E_INPUT_SUPERSEDED`), which every verifier library of `spec-0.4.0` must agree on; and formula cases (`generate_formula.py`: grammar sources, some mutated, evaluations over a fuzz world, and decimal cases for every operation), on which an implementation of the formula dialect must agree with the reference to the last digit (`FORMULA_RUNNER`; without it the reference runs them twice, which checks its determinism). `LIBS=0.3` checks libraries of `spec-0.3.0`: the vector set is then the `spec-0.3.0` vectors only. A runner that does not implement a kind of vector (the verifier libraries, for `formula`, `formula-eval`, `excel` and `decimal`) prints `{"id": ..., "error": null, "skipped": "<kind>"}` for it; `compare.py` leaves that runner out of that case, checks the line has nothing else, and reports the skips. The reference tool never skips.

Since `spec-0.4.1` one more set (`generate_041.py`): `pending` envelopes and results served at a job URL, checked against the original request (the echoed request, the job and `poll`, the binding of a job's result, `E_JOB_UNKNOWN`), and mesh documents resolved with their key documents (`mesh` vectors: host and proto agreement, URLs on another host, placeholders, required endpoints, unknown members, malformed text, failed retrievals). `LIBS=0.4` checks libraries of `spec-0.4.0`: the vector set is then the `spec-0.4.0` vectors only, and the `spec-0.4.1` set is run by the reference tool alone, twice. `LIBS=0.4.1`, the default, runs it through every library.

Since `spec-0.4.2` one more set (`generate_042.py`): pinned cell URIs (`fn_hash=` placed, repeated and malformed, and an argument named `fn_hash`), envelopes answering pinned and unpinned requests (the `fn_hash` echo, `trust` `computed` against the signer and the mesh asked, `E_NAME_UNBOUND`, `E_SLICE_AT_CELL`), pages of the slice endpoint (order, membership, `asof`, the cursor, `next`), and batches (order, length, item shape and status, refusals). `LIBS=0.4.1` checks libraries of `spec-0.4.1`: the `spec-0.4.1` vectors only, and the `spec-0.4.2` set by the reference alone, twice. `LIBS=0.4.2` runs it through every library. The kind `call` is, like the formula kinds, for implementations of the dialect: verifier libraries skip it.

Since `spec-0.4.3` one more set (`generate_043.py`): licence inheritance cases (kind `licence`: random multisets of input licences, open, unlisted SPDX ids, case variants and licence URLs, under random declarations open, closed or opening later, for this function or another), key documents with `declarations` (kind `keys`, about half mutated: another host or a subdomain, a bad name, licence or instant, `valid_to` not after `valid_from`, members missing or extra, an empty array or object, 64 or 65 names, 16 or 17 entries), and entitlement cases (kind `entitlement`: computed receipts over stored inputs, some read as one slice, carrying the licence the rule gives or another), and error envelopes with `E_FOREIGN_UNAVAILABLE` or another code, with or without a `detail`, with 502 or another status, or under another outcome. The implementations must agree on `key_ids`, `declarations`, `licence`, `reason` and `entitled`. The kinds `licence` and `entitlement` are for verifier libraries too (SPEC.md 8.5, 10.3), not skipped. `LIBS=0.4.2` checks libraries of `spec-0.4.2`: the `spec-0.4.2` vectors only, and the `spec-0.4.3` set by the reference alone, twice. `LIBS=0.4.3` runs it through every library.

Since `spec-0.5.0` (part one) one more set (`generate_050.py`): mesh documents of an unrooted host (`local.invalid`) and a rooted one whose URLs are on the host, on a loopback origin (`127.0.0.1`, `[::1]`, `localhost`, with or without a port) or elsewhere, some mixing two origins or misspelling the address or port; `pending` envelopes whose `poll` is loopback, against requests naming an unrooted mesh, a rooted one or none; the inheritance rule's arguments, some malformed; and entitlement cases whose inputs or manifests are missing, of another hash or not signature-valid. With classes (step 1.3b part A), the set also holds object key encodings, nested and mutated (kind `key`), and string key values in four scripts under each key normalisation (kind `normalisation`). The new vector kinds `class`, `normalisation`, `key` and `describe` are for verifier libraries; the classes' method calls, dispatch and defaults are in the kinds `formula`, `formula-eval` and `call`, for implementations of the dialect. `LIBS=0.4.3` checks libraries of `spec-0.4.3`: the `spec-0.4.3` vectors only, and the `spec-0.5.0` set by the reference alone, twice. `LIBS=0.5.0`, the default, runs it through every library.

Since `spec-0.6.0` (part one) one more set (`generate_060.py`, 90 vectors, written by it and not by `generate.py`): stored receipts with `source` (kind `receipt`: all five members, only the three required ones, and the invalid shapes, each with its code: `source` with inputs, an extra or missing member, a `name` equal to the publisher's host, a bad name, instant, `sha256` or `takeover`, an `http://` or 513-character `url`, and `retrieved` after `issued`); envelopes with trust `relayed` and `primary` against a receipt with `source`, the `scenario` outcome (value and slice overrides, `solved`, and the request's `overrides` and `solve` echoed, with their checks at step 5), and `cycle` on `E_EVAL_UNAVAILABLE` (kind `envelope`); requests with digit-led words, quoted and unquoted, in string and number positions (kind `call`); describe answers with `tests` and `source` in a method entry, and function answers, held and not held (kind `describe`); and mesh documents with a `whatif` endpoint, valid, and with a placeholder (kind `mesh`). The kinds `receipt`, `envelope`, `describe` and `mesh` are for verifier libraries; `call` is for implementations of the formula dialect (it is skipped by the others). `run.sh` does not select this set by `LIBS` yet: how the libraries run it is the coordinator's to set when the cross-check of spec-0.6.0 is made.

Since `spec-0.6.1` one more set (`generate_061.py`, 142 vectors, written by it and not by `generate.py`, all new files): names with a DNS segment after the host (every row of SPEC.md 2.3's table as a `define`, a `cell` and a `uri` vector, accepted and refused: a hyphenated domain, a punycode label, three labels, an uppercase letter, a trailing dot, an underscore, an empty label, a leading or trailing hyphen, an all-digit last label, a DNS name as the last segment, labels and segments over their limits, a name of exactly 512 characters), a function with such names in `inputs`, classes (a dotted namespace segment and steward, a dotted method name refused), rooted and unrooted hosts with a `.invalid` later segment, receipts and envelopes (a relayed receipt under a name with a DNS segment, `primary` and `unverified` decided by the first segment alone), formula bodies with a dotted segment beside minus, divide and a method call (kinds `formula` and `formula-eval`, the latter with outputs taken once from a scratch copy of the reference with the 0.6.1 lexer rule), the `test_case` convention (a `jcs` vector for the case id, the function, a URI, receipts and envelopes of a test cell and of a counterexample) and describe answers with and without `publisher` (kind `describe`). The verifier libraries run every kind of it but `formula` and `formula-eval`; the new vectors are expected to fail against libraries of `spec-0.6.0` (a dotted later segment is `E_CANON_NAME` there, `publisher` is `E_DESCRIBE`) and the reference tools of `spec-0.6.0`, and all older vectors must still pass. `run.sh` does not select this set by `LIBS` yet: how the libraries run it is the coordinator's to set when the cross-check of spec-0.6.1 is made.

```sh
crosscheck/run.sh 1000 7                 # needs Docker and git; libraries of spec-0.5.0
LIBS=0.4.3 crosscheck/run.sh 1000 7      # libraries of spec-0.4.3
LIBS=0.4.2 crosscheck/run.sh 1000 7      # libraries of spec-0.4.2
LIBS=0.4.1 crosscheck/run.sh 1000 7      # libraries of spec-0.4.1
LIBS=0.4 crosscheck/run.sh 1000 7        # libraries of spec-0.4.0
LIBS=0.3 crosscheck/run.sh 1000 7        # libraries of spec-0.3.0
```
